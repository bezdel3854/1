# BingX BTC/ETH USDT perpetual paper bot

**Research + local paper trading only. No real order code, exchange credentials, or live mode.**

Первый честный результат: фиксированная EMA/RSI-стратегия **убыточна**. На данных BingX 28.07–25.10.2026 виртуальные 1000 USDT стали **899.94 USDT** (56 сделок), затем бот остановился по лимиту просадки. Отложенная проверка последних 30 дней с отдельным стартом 1000 USDT: **902.27 USDT**, 45 сделок. Прибыльность не доказана. Подбор параметров после результата не проводился. Полный отчёт: [reports/validation/REPORT.md](reports/validation/REPORT.md).

## Исследование других подходов

После интернет-поиска изучены проверяемые конкурсные результаты и публичные подходы Williams, Unger, Carlile, Scherman, Dennis/Eckhardt, Carver и Raschke. Это не рейтинг всех мировых счетов. [Источники и ограничения переноса](research/TRADERS_AND_SOURCES.md).

Реализованы восемь фиксированных вариантов, включая исходный baseline, Donchian, EWMAC, откат, mean reversion, volatility breakout и две объединённые модели. **Ни один не прошёл предварительный фильтр.** На уже просмотренной истории даже наиболее близкие к нулю варианты не подтвердили устойчивость; объединение не дало плюс. [Полное сравнение](reports/approaches/REPORT.md).

```bash
python -m bingx_bot.cli research --data data/history --out reports/approaches
python -m bingx_bot.cli paper --strategy regime_composite --db runtime/composite.sqlite --once
```

Новые модели по умолчанию только записывают решения, **без виртуальных входов** (`observe_only=true`). Для отдельного экспериментального paper-счёта возможность входов включается явным флагом `--enable-experimental-entries`; это не реальная торговля и не автоматическое одобрение стратегии. Смена модели требует отдельной SQLite-базы. Стратегии 2–8 используют максимум 48 часов удержания и цель 4R, baseline сохраняет исходные настройки. Trailing/выходы действуют со следующей свечи в бэктесте; в paper — со следующей свежей проверкой закрытого сигнала.

Важное исправление интерпретации: прежние 30 дней holdout уже просмотрены. При поиске других стратегий вся сохранённая история теперь считается данными разработки. Новый `research` не называет поздний участок независимым holdout, учитывает восемь попыток в bootstrap-диагностике и не повышает кандидата автоматически.

## Что реализовано

- BTC-USDT и ETH-USDT, бессрочные USDT-фьючерсы; общий виртуальный депозит **1000 USDT**.
- Long/Short: пересечение EMA20/50 и RSI14 на закрытых **15m**, фильтр EMA20/50 закрытого **1h**. RSI Long 50–70, Short 30–50. Прогрев 200 свечей 15m и 100 полных 1h. Часовые свечи агрегируются из четырёх полных 15m.
- Стоп = 2 ATR14 от фактической моделируемой цены входа; цель = 2 расстояния стопа; максимальная длительность 32 свечи (8 часов).
- Плановый риск **до 0.5% текущего equity** на сделку, включая комиссии входа/выхода, проскальзывание выхода и резерв funding 10 bp. Это 5 USDT при начальном счёте. Гэп, задержка исполнения и необычный funding могут превысить бюджет.
- Общий плановый риск до 1%, не более одной позиции на символ; плечо 2x, isolated-margin **модель**, notional каждой позиции до 1x equity. Проверяются минимальный объём, шаг и минимальная сумма контракта из текущего snapshot API.
- Дневная остановка при снижении equity на 2% от начала суток **UTC**, закрытие виртуальных позиций, блок до следующих суток; глобальная остановка при просадке 10% от peak, без автоматического сброса. Порог может быть пересечён из-за дискретного контроля/гэпов.
- Бэктест: вход на следующем open; adverse slippage 2 bp на каждой стороне; taker fee 5 bp на каждой стороне (предположение); реальные funding rates + settlement marks; стоп первым при двойном касании; гэп через стоп исполняется по худшему open; нет благоприятного улучшения цены тейка при гэпе.
- Реальный публичный bid/ask для paper-входов/выходов, фильтр spread 10 bp, отбраковка котировок старше 30 секунд. Поверх bid/ask применяется моделируемое проскальзывание. Стопы проверяются по котировкам с интервалом цикла, а не гарантированно внутри биржи.
- SQLite WAL/FULL: атомарное сохранение счёта, позиций, cursors и журнала; восстановление после перезапуска, запрет второго writer, защита от повторного сигнала. Вход только в первые 60 секунд после закрытия свечи; пропущенные сигналы не воспроизводятся.
- Dockerfile, Railway IaC-шаблон, HTTP healthcheck, graceful shutdown, GitHub Actions workflow.

## Быстрый запуск (Python 3.12+, Linux/macOS)

Runtime зависит только от стандартной библиотеки. Установка зависимостей не нужна.

```bash
python -m unittest discover -s tests -v
python -m bingx_bot.cli backtest --data data/history --out reports/reproduced
python -m bingx_bot.cli paper --db runtime/paper.sqlite --once
python -m bingx_bot.cli paper --db runtime/paper.sqlite
```

Для непрерывной работы нужен постоянно включённый сервер. Локальная проверка из чата не означает, что бот продолжает работать после завершения сессии.

После остановки worker:

```bash
python -m bingx_bot.cli export --db runtime/paper.sqlite --out trades.csv
```

Режим `MODE=live` отвергается. API-клиент содержит только allowlist публичных GET-маршрутов. Ключи BingX нигде не читаются и не нужны.

## Данные и воспроизводимость

`data/history` содержит по **8544** закрытые свечи 15m и **267** funding settlements на BTC и ETH, UTC, 89 дней. Сжатые JSON открываются loader автоматически; SHA256 считается по исходным JSON-байтам. Проверяются целостность, OHLCV, пропуски, порядок, совпадение временной сетки двух активов и грубое покрытие funding (разрыв >12h отвергается для диапазонов >=24h).

Попытка получить год истории обнаружила пустые окна свечей за 365 и 180 дней назад. Эти данные не заменялись свечами другой биржи и не синтезировались. Проверка ограничена доступным периодом. Текущие правила контрактов не являются историческими правилами.

Повторная загрузка (требуется сеть, границы кратны 15m, конец не включён):

```bash
python fetch_history.py --start 2026-07-28 --end 2026-10-25 --out data/new_history
```

У BingX глубина истории может измениться, поэтому для воспроизведения сохранён готовый snapshot. `manifest.json` содержит источник, время получения, параметры контрактов и хеши. Стратегия фиксирована; разделение — 7 дней прогрева, первые 52 дня проверки и последние 30 дней holdout. Отдельные месячные forward-сегменты сбрасывают капитал; это не подбор параметров и не полноценное обучение walk-forward. В `results.json` сохранены также стресс издержек (fee 10 bp, slippage 5 bp), кривые equity и сделки CSV.

## Что проверено и что остаётся

См. [docs/VALIDATION.md](docs/VALIDATION.md). Просадка измерена по open/close, не по непрерывной внутрисвечной траектории. Ликвидация — приближение isolated margin с maintenance 1%, торговыми ценами вместо mark и без точных tier/insurance fees. При обычном стопе 2 ATR при плече 2x ликвидация ожидается дальше стопа, однако гэпы и сбои сохраняют риск.

Paper использует живые котировки, но не проверяет исполнение реальных заявок, очередь и ликвидность. В случае недоступности данных виртуальные выходы ждут свежих котировок; это не защита открытого биржевого счёта. Реальная торговля намеренно не реализована.
